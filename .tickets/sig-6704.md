# Session resolver: auto-detect + snapshot capture

From cwd + opts, resolve to a Session: auto-detect PR across worktrees, create or load session, capture a new snapshot when head SHA has advanced.

## Design

New file `diff/resolve.go`. Depends on S1 (storage), S2 (gh), S3 (worktree).

Public API:
- Resolve(ctx, opts ResolveOpts) (*Session, *ParsedDiff, error)

ResolveOpts: {SessionID string; IncludeDraft bool; CWD string}

Algorithm (per brief):
1. opts.SessionID set → load and return
2. else: walk worktrees; for each, gh pr list filtered to that worktree's branch; union candidates
3. zero PRs → error with `gh pr create` hint
4. one PR → use it
5. multiple → return ErrPickerNeeded carrying candidates (worktree path + branch + PR title + base) for caller to resolve
6. session exists and head_sha unchanged → no-op
7. session exists and head_sha changed → capture new snapshot (write diff.patch + meta.yaml; append to session.snapshots; update head_sha; save session; update sessions.yaml)
8. no session → create new (UUID, fetch initial diff via gh pr diff, write snapshot, save session, upsert sessions.yaml)

Snapshot meta.yaml: observed_at, branch, head commit message (`git log -1 --pretty=%B <head>`).

## Acceptance Criteria

- Resolve handles all branches of the resolution order from the brief
- New session creates correct directory layout under XDG base
- Existing session + new head_sha → new snapshot dir + session.snapshots append
- Existing session + unchanged head_sha → no snapshot churn
- sessions.yaml index upserted on create / update
- ErrPickerNeeded carries candidate list with worktree path + branch + PR title + base branch
- Integration test: tempdir + real git init + mocked gh binary drives the full flow
